# 仿真通道自主完成安装与故障恢复：六机现场记录（2026-09-30）

## 适用范围与主动处理边界

用户已授权更新指定设备、部署集群或修复指定 App 时，同一任务范围内的检查、传包、安装、普通确认弹窗、断线重连、回滚与验收属于实施步骤。不要把它们拆成“是否允许继续”的重复提问。先读取目标设备的现有仿真 ID、可信主机名/SSH 指纹、对应办公 ID、当前版本和回滚点；对每一步用工具直接获取现场证据。只有原授权未覆盖的新目标/不可逆后果、设备身份不符、平台强制本人认证或无法判断弹窗归属时，才请求最小必要输入。硬件令牌 PIN、密码、生物识别只由持有人在设备本机输入，绝不代输、读取或记录。

仿真工具能处理普通 GUI 确认：先 `vibekits.device.ui_inspect` 找到**目标 App 的窗口**、内容、控件和所属进程，再用 `vibekits.device.ui_action` 点击与任务一致的“允许/继续/重试”。一次看到截图上有“允许”不够，窗口可能重叠。529 Mac dev345 覆盖后同时有 86Box 和 VibeKits 的“本地网络”授权弹窗；通过 `UserNotificationCenter` 的 AX 窗口文字区分，只点击 VibeKits 的允许，随后 `cluster.rooms` 从 `No route to host` 变为 live/connected，hbbv 心跳恢复。此现象暴露升级重复请求本地网络权限，属于仍需修复的授权延续缺陷，不能靠自动点击宣布产品门禁通过。

## 远程更新的可复用判断链

1. `simulator.connect` 必须返回目标路由 ID、`p2p_or_relay`、可信主机名和指纹、SSH/MCP ready。紧接着做一次真实 `ssh_exec` 或 `simulator.call`。`connected=true` 可能是缓存连接，真实 SSH reset 才是当前有效证据。连接失败先查同机办公 ID 对应通道、发起端 App/Harness，再判断目标服务；不能把 `Remote desktop is offline` 解释成电脑关机。
2. 读取**运行中的**主程序路径、版本、签名、仿真开关、两个 ID、房间与心跳。目录名可能留着 dev319，但其中实际 EXE 是 dev340；不要凭路径标签推版本。升级前冻结原 ID、主机指纹、安装身份/配置哈希、旧版包和房间状态。候选必须签名有效、版本正确、空间足、回滚完整。
3. 传包后在目标机重验字节数、SHA-256、签名。58 dev345 安装器 258641248 字节，SHA-256 `B73D833BCA6713E9BACC57C01732EE67D9CB0833B3F6B4B02F8247E4227B81FB`，与 xzl 本机重算一致。xzl 的 SFTP 上传小文件也失败，不能循环重试；已验证方案是仅允许其当前 `192.168.3.80`、一次性 Bearer、短时 HTTPS、目标本机 CA/主机名验证、传后关闭监听和删认证文件。`--ssl-no-revoke` 只绕过私有测试 CA 在 Windows Schannel 的吊销查询，不关闭 CA/主机名验证。任何无认证 HTTP 被平台拒绝后不得换工具绕过。
4. Windows 先备份当前**实际运行目录**，以文件总数、字节数和主 EXE 哈希验完整。58 dev340 回滚副本是 29,936 文件 / 908,574,615 字节；xzl 是 29,935 文件 / 906,220,394 字节。两者主 EXE SHA 都是 `9172AF289700587F6A6DC0565B7E6A3CC671C82A0B4EE530F669C8052E1C4916`。设备目录不同，不把 58 的 D 盘硬编码到仅有 C 盘的 xzl。
5. 登录用户交互会话中注册仅执行固定已签安装器的独立计划任务，锁定其用户、`Interactive`、精确 CMD 和日志路径，再启动。仿真通道会因旧 App 被替换而断开；此时读取独立任务的退出标记/日志，或等待并重连**原 ID**。不要因 SSH 返回 255 盲目二次启动。58 与 xzl 本轮安装任务均退出码 0，原 ID 分别 `4240650696`、`6192992780` 重新连通，主机指纹不变；实际 Session1 主程序 dev345/build2345、签名 Valid、EXE SHA `7A832A61158BA53D8AA9B950ECBAA81EC76FC7B242C0001A530D57A7E9A3BCE5`，Harness relay/Node 同目录运行，房间实时心跳恢复。只有这些证据齐全才叫覆盖升级通过。
6. 若 30–60 秒后原仿真 ID 仍离线，先从独立 hbbv 心跳判断是否正在安装；再用登记的同机远程办公 ID 打开桌面，检查 Inno 提示、程序路径和登录会话。办公窗口也必须核对设备身份，不能假定一个在线办公 ID 必然是目标机器。若显示“文件被占用，重试/忽略/取消”，仅当精确旧进程已退出且安装器仍在等待时点击“重试”；不选忽略掩盖错误。随后启动原安装路径 App，再用原仿真 ID 重连并全量验收。

## 此轮疑难问题和修复

- 58 dev345 内层签名：用户输入 PIN 后不能立即报成功。读取 `sign-inner.status=PASS`、报告 224/224 有效、主程序哈希；Inno 打包进程长时间压缩 29,072 个文件，即使 SSH 调用返回 255，`ISCC.exe` 和日志仍持续增长，不能重复打包。打包 `package.status=PASS` 后才签外层；外层再次通过交互 Session1 的 SafeNet PIN，`sign-outer.status=PASS`、安装器 Authenticode Valid。PIN 由用户在目标机输入，不通过聊天接收。
- 58 独立安装任务的第一次创建命令返回 PowerShell 1，但只读检查发现任务已注册且 Ready、旧版未改变；核对用户/动作后单独 `Start-ScheduledTask`。避免把“脚本整体报错”当作“前面没有产生任何状态”，也避免重复注册/安装。
- 132 Mac dev345 脚本写 `STARTED` 却仍不能连接：旧 dev344 回滚副本的进程抢占 32147/32148，`lsof -p <PID>` 的 `txt` 指向旧二进制。只 TERM 已核对的旧 PID，再启动原安装路径的 dev345，随后两个端口由唯一新版 PID 占用、房间心跳恢复。不能只看 `pgrep` 命令行或脚本退出码。
- Windows 只读 PowerShell 用正则 `-match 'D:\KEMI...'` 时反斜杠被解释为转义，导致验收脚本失败；改成对固定路径的 `-like 'D:\KEMI...*'`，再重跑同一个只读门禁。验证脚本错误不等于安装失败。

将现场证据按时间记录为：设备/原 ID → 现象 → 精确进程/日志/窗口 → 根因或未证假设 → 最小动作 → 原 ID 重连、运行版本、签名、房间心跳。每次问题解决后追加具体的新例证，不把未复现的推断写成通用事实。
