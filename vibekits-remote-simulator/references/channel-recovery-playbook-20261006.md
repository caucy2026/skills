# 仿真失败时复用同机远程桌面的排障路径

遇到connect失败，先读本流程和当前设备映射，不停在报错说明、不重复请求已有操作授权。已授权的同机办公ID是实际备用管理通道；集群心跳、仿真、远程办公分别验证。下述路线不保证绕过锁屏或认证，PIN与身份变化边界仍保留。

1. 保存时间、控制端版本、原仿真ID、完整错误code、实际connection_status与当前房间心跳；本机更新后not_connected先恢复原可信仿真连接，不能判对端离线。若有活跃签名/升级只观察，不再安装或重签。
2. 分流：控制桥未连、native transport、SSH引导、MCP、房间HTTPS/心跳、进程及物理网络分别列证据。SSH bootstrap HTTP500是目标控制端点异常响应，既不证明物理离线，也不证明锁屏就是根因。源码可能丢弃500正文，应取得实际错误/日志后才归因。
3. 查询已经登记且核验同机的远程办公ID。用户禁止连接离线桌面时，先在办公主页查当前在线指示；在线才按原授权连接，离线不尝试恢复。不能仅从另一设备自报或名称相似决定同机关系。
4. 原恢复工具优先。在远程办公本机工具无对应API时，使用已授权UI路线。界面点击不生效先核对窗口/前景：本次macOS必须对实际窗口执行其公开的Raise动作，随后点击主页才成功；不要重复盲点或自行启动第二实例。索引随界面变化刷新；坐标必须来自新截图。
5. 连接后检查窗口标题、目标主机和原办公ID。锁屏与登录PIN窗口是真实阻塞：用户在已打开的目标窗口输入，智能体不输入、不读取、猜测、复制PIN，不关安全保护。已有严格可信SSH备用入口可按原授权独立只读检查；隧道登录不等于系统账户认证，不能换账号/钥匙或扩大授权。没有该入口就保留具体等待，而非声称已恢复。
6. 解锁后检查目标VibeKits实际路径/版本/PID、原仿真ID、仿真开关、SSH服务、当前controller授权及目标日志。优先恢复原已授权开关；不要重装、清凭据、改ID、批量结束进程或把Session0启动当作交互GUI已打开。
7. 恢复后用原仿真ID重新连接，严格核对原指纹、实际只读MCP和SSH各自状态；再配置用户指定新服务，按原申请/批准或原成员身份恢复入房，核验客户端实时状态与新服务新鲜心跳。成功回执不代替稳定观察，未完成设备继续单独列出。
