# 服务器端口统一管理

## 文档入口

先读 [本地服务器索引](references/local-servers.md)，按目标服务器定位其唯一权威端口文档，再读取相关服务配置。此技能为全局入口；端口事实仍在每台服务器的权威文档维护，不在不同项目复制多套可编辑台账。

没有匹配目标时，先从当前项目部署文档确认主机、环境、服务与已有端口表，不能套用索引中的另一台机器。只有确实缺少影响选择的目标信息时才询问用户。其他机器复用技能时先更新本地索引。

## 查询与记录

- “谁占用”逐项给出端口、传输协议、服务/项目、用途、配置依据、文档状态和现场核验时间；TCP 与 UDP 分行。不得把 hbbs/hbbr 合成无法辨认归属的连续端口段。
- 区分：设计预留、已配置、已部署、现场已验证、不启用、已释放。配置和源码不是当前进程证据；没有现场证据时绑定地址、PID、运行状态记未知。
- WebSocket/HTTP/HTTPS 是 TCP 上的应用协议，不另计一个独立端口；SSE 可与网页/API 共用 HTTPS。
- 端口冲突以服务器/网络命名空间、TCP或UDP、IPv4/IPv6、绑定地址和端口判断。注意通配绑定、IPv6 dual-stack、容器映射和 socket activation；同数字在不同主机并不冲突。
- 只输出服务所需元数据。不要读取/打印私钥、密码、令牌、完整进程环境或含凭据的启动参数。

## 选择和预留

1. 查权威表、部署配置和必要源码，排除已分配、设计预留和明确保留的端口。端口表遗漏不代表空闲。
2. 在既有授权内，通过正确目标的已授权 SSH 会话只读检查 listener、socket unit、容器端口映射与运维预留；生产检查前读取该服务适用的运维约定。不要通过外网连接失败推断空闲。
3. Linux 可用 `ss -H -lntup` 和 `systemctl list-sockets --all --no-pager`；仅在确有容器时读取其端口映射。权限不足看不到进程时明确说明，不猜 PID。防火墙放行证明可达策略，不证明占用；无 listener 也不能排除未启动但已预留的服务。
4. 不能登录或证据不足时，可按用户已授权的设计任务登记“设计预留，实时占用待核验”，保存失败原因；不能标已验证空闲。不要索取聊天明文密码，不自动新增 SSH 公钥，不盲试其他项目密钥。
5. 用户要求的预留/登记直接写权威文档，无需重复口头确认。写前重读相关段落避免并发覆盖；同端口出现冲突先保留双方记录并标冲突，不停止原服务或强占。选择替代端口后同步直接相关设计引用。

## 变更、部署与释放

文档登记不会授权启动 listener、改防火墙、重启、修改绑定或发布。仅在用户原请求已涵盖这些操作时沿服务既定流程执行；不要人为增加已获授权工作的审批轮次。

部署前必须再次核验预留，现场结果带时间；分配不是操作系统排他锁。部署后核对实际绑定、服务归属、应用健康和必要外部可达性，才能记录已部署/已验证。证据只说明当时状态，后续不得自动当作永久事实。

释放前核对进程、socket activation、容器映射、服务配置和运维预留确已解除，记录旧用途、释放时间和依据；保留历史，不以进程暂时停止为由释放。hbbc、hbbs、hbbr 独立维护；端口任务不授权停止或重启它们。

## 最小台账字段

每台服务器文档记录：主机/环境标识、端口、传输/应用协议、绑定地址（未知则明确）、服务/unit、项目路径、用途、分配状态、来源、最后现场核验时间与结果、变更记录。未知项不补造。

维护权威表后更新直接相关项目的入口链接或明确标注日期的只读快照。报告实际修改位置、端口归属和未核实项；仅查询时不扩大为部署或全网扫描。
