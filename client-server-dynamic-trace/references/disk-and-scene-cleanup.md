# 注入采集磁盘与现场收尾

适用于获授权的原版前端、后台、我方服务及宿主采集目录；不改变现有注入、停写、退出或轮转路线。

## 每轮开始与采集中

- 开始前核宿主、当前XP及WinServer实际日志盘剩余空间，精确区分各机磁盘。列本任务旧BIN/EXE/日志路径、大小、所属runId/PID及是否仍有写入，不能拿上次余量当当前值。
- 先清已经不用、可重建且确认无进程使用的本任务一次性EXE/旧注入BIN。需要保留的原始迹线先归档并回读哈希；不是证据就不要长期堆积。不得通配删除源码、原版程序、数据库、虚拟磁盘、现役DLL或未归档证据。
- 采集必须事先设结束时间、最大事件数/字节数、日志轮转和最低磁盘余量，按本次样本量给具体值写入run记录；不能无限期注入采集、让BIN一直增长。收齐所需事件即结束，不为等待后续任务持续写盘。
- 采集中观察文件增长与余量。触及任一上限、余量不足或增长异常，按成熟入口停止本轮采集/停写、封口轮转，保留失败与健康回执；未核恢复之前不继续扩大采集。不要为了清理重启健康服务、强杀loader或热卸带断点DLL。

## 每轮结束必须清理现场

1. 按成熟流程结束本轮collector、释放输入；驻留观察器的模块生命周期与日志写入分开处理，不能把停止采集等同卸载DLL。
2. 封口日志，保存必要原始证据、命令、制品/PID/代次、哈希到持久目录并回读；长期目标/交接台账不只存临时目录。
3. 精确删除本任务已退出的一次性EXE、旧PID BIN及归档验证后的冗余副本。仍活跃或归属不明的文件不删，列入待清理并采用原有停写/轮转方法。其他同事文件不代删、不为常规清理打扰。
4. 回读文件是否已消失、日志是否确实停止增长、磁盘余量及前后台健康。记录清理前后字节数、已删/保留/失败/待清理；删除命令发出、删除失败或旧记录不算空间已释放。

用户要求及时清理不用文件，不等于授权删掉活跃探针或唯一证据。复用既有授权与成熟路线，不重复申请相同操作。


## 自己创建的资源自己收尾：开发统一准则

用户要求效率第一：任务只保留当前必需的实例和采集，优先复用成熟路线并后台运行；需要前台操作时短时取得所属窗口/输入锁，动作结束立即释放输入、归还前台，不长期占着用户桌面。

- 谁创建APP、子进程、collector、线程/定时器，谁负责结束；记录runId、PID、完整路径、控制socket和所属任务。样本/验证结束立即关闭自己的实例，不用的旧实例不堆积。用户明确要求保留的验收实例单独记用途和收尾时点。强制关闭只针对当前授权的精确PID/路径，回读退出；不以同名通杀替代身份核验，不自动重启或终止XP/共享后台。
- 谁打开文件、文件描述符/句柄、映射、锁、数据库连接/事务、socket，谁在成功、异常、取消和超时路径释放。优先RAII、with/context manager、try/finally；先停写/flush/结束事务，再关闭连接与句柄，禁止用下次重启代替释放。结束检查仍有无所属活跃进程、锁或写盘；进程已退出会释放其OS资源，但不是后台业务保存已通过的证据。
- 谁生成临时注入BIN/EXE、分析副本、测试数据库和编译产物，谁在不用后清理。先归档必要且脱敏的证据/复现源并回读身份，再确认进程退出、文件无活跃使用，精确删除可再生成的冗余文件；记录实际删除与释放字节。不得通配删源码、用户数据库、VM磁盘、现役DLL或唯一未归档证据。驻留探针先按成熟入口停采集/封口，不热卸活跃hook、不强杀loader来省清理步骤。
- 清理过程发现旧实例/文件归属不明则列待核，不把别人的资源当自己资源。只有用户明确要求协调或确有资源冲突时合并通知；本次用户强制清理指令不扩大成以后例行终止同事运行。清理失败和用户中断的样本如实记失败/中断，不算业务验收成功。

每次离开现场前必须核：自己的不用APP已退出、输入/前台已归还、文件/句柄/事务/socket/锁已释放、临时文件已清或有具体保留理由、证据可回读。资源收尾不是删除/暂停完整目标；完成收尾后继续原目标的下一项必要工作。

## 编译替换前保留已验证程序

复用可变构建输出路径前，先把仍用于验收或回滚的程序、实际源码输入、编译/链接命令、直接对象及依赖身份清单复制到该run的独立目录，回读程序SHA匹配原回执后再覆盖工作输出。保留当前候选及必要的上一基线，不无限保留每次编译；唯一验收制品不能作为普通旧BIN清理。

2026-10-06复活链47a程序被后续诊断编译覆盖；一次精确重建的SHA仍不同，原运行证据可保留但不能宣称原程序已恢复或当前路径仍指向旧制品。发生此类缺失应立即标注证据限制，有界重建并比较实际SHA；不反复重建，不把输入相同当作二进制相同。
