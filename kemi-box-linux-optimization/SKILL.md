# KEMI Box Linux 优化

先确认设备、实际运行包和源码提交。101 为 ARM64，88 为 amd64，具体身份、glibc 和当前运行用户现场回读。沿项目原仿真或可信备用通道操作。备用 SSH 若登录另一用户，只用于核实状态，桌面启动和 Keyring 验收回到原桌面用户。设备恢复复用 [bot-kemi-box](../bot-kemi-box/SKILL.md)，通用构建和验收复用 [linux-desktop-build-acceptance](../linux-desktop-build-acceptance/SKILL.md)。

## 构建与容量

- 大量写盘前用实际目标卷的可用字节减去项目保留线。估算剩余编译对象、临时链接输出和打包副本各自的峰值。带符号对象、解包依赖及打包目录经常远大于最终压缩包。旧版成品大小只作量级参照。
- 内存触发保护后，读取构建器的业务回执、退出原因和原子进程状态。systemd 显示 succeeded 也可能只是外层控制器成功写完失败回执。确认终态后保留合格增量对象，使用独立续建回执，按证据降低并发，并同步调整顶层 make 与子构建并发。若剩余空间不足以通过原门槛，先处理有证据的闲置生成物。
- 大目录先按源码、工具链、可再生输出、正式包和当前引用分开。清理旧 Cargo 输出前核实构建终态、目标路径、活动引用、保留的源码和验收证据。硬链接要核 inode 和链接数。下载残片只有在完整归档符合锁定 SHA 且残片可证明冗余后才清。逐批回读删除路径和目标卷可用字节，复用 [kemi-storage-cleanup](../kemi-storage-cleanup/SKILL.md)。
- 隔离 SDK 中验证实际工具和依赖。若 Qt 使用编译期引擎绝对路径，可把已完成的引擎只读绑定到隔离环境内的正式安装路径，configure 后核生成的路径，再编译。最终包从正式位置冷启，并核对实际映射的库。保留原设备 glibc 基线，私有运行库同时检查 GUI 和 sidecar。

## 性能与硬件验收

- 性能对比固定设备、实际包、输入和操作顺序。秒表检查前台动画和真实输入连续性，资源采样涵盖完整进程族。严格空闲时记录 PSS、单核等效 CPU、监听进程及仿真实调。项目的 G6 与帧间隔门槛沿用原验收规则。
- H.264 与 H.265 分别验真实双机协商、发送端硬编、接收端硬解及持续出帧。将日志、硬件组件和实际帧绑定到同一会话及候选包 SHA。单独硬件探针可定位能力，产品会话仍须验收。
- ARM64 OMX 先实测组件支持的像素格式，再统一探针与产品输入。101 已见 NV12 被编码器拒绝而 YUV420P 可用，也见首个访问单元未立即出帧。接受输入但暂时无输出时采用有界等待。解码端按实例管理回调、端口重配、缓冲回收和 EOS，能力广告须收到实际可用帧。新分辨率或厂商格式先用已知色度样本核验。

## 应用交付

- 同一 Linux 下载包可包含 amd64 和 arm64 两个载荷。核外层哈希后按实际架构流式取对应成员，再验证内层哈希、包名、版本和架构。两机以同一外层 SHA 验证安装、自更新、冷启与功能。
- 本机版本从安装登记或系统元数据读取。Debian Version 可独立显示，商城构建号用于更新判断。AppImage 登记完整版本名，旧登记仍可显示构建号。实测应用中心安装、打开、卸载、复制下载链接、二维码和关闭。卸载前确认实际归属和运行状态，保留用户数据。
- 登录自启在原桌面用户下验证实际重登、单实例、仿真实调与原 Keyring 可用性。安全凭据不得进入证据。扫码验收区分公网协议、实际手机扫码和原字段回填，各自记录结果。

## 持续更新

每次验证完可复用的新方法，随本次工作更新此技能及团队技能仓库。项目记录保留设备与包标识、源码提交、原事务、输入、实测结果、清理回执及未验项。技能只记录通用做法、适用条件和失败信号。未完成实机验证的方法明确标为候选。发现旧方法已被证据推翻时，更新原段并链接项目记录。
