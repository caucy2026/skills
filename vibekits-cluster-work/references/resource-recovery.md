# 构建资源不足与升级恢复：已验证的方法

仅用于已授权设备、已核空闲客户端和本任务构建。具体ID、路径、PID、出生时间、门槛与包哈希从当前项目台账读取。

- 分清机器可用RAM、系统commit和单个仿真命令的进程预算。PS7读取自身配置时OutOfMemory可能来自命令进程的512MB预算，不是执行策略拒绝；先保留错误。长构建沿既定独立交互任务运行，正常PS7 -File与策略不变。禁止绕过真实UnauthorizedAccess。
- 不降低既有构建门槛、不结束别人的软件。资源只差少量时，核对本任务客户端实时界面、任务状态、精确路径、签名、PID及同API出生时间。若确已空闲，可在独立恢复守护就绪后正常关闭该客户端；正常关闭超时后，仅在授权涵盖且身份fence仍匹配时结束这一实例。
- 恢复守护必须由独立交互任务持有，检查真实PID/路径/会话。构建finally恢复原已核签名程序，另有有界超时恢复；守护终态后再回收临时任务登记。旧版本恢复后读取新PID，不能沿旧PID继续签名或安装。
- 桌面与仿真配合观察同一事务。窗口不存在时用登记远程办公ID打开新连接窗口并核标题，不停止办公服务。文本发送成功不代表真实远端字符串正确；确认焦点与完整目标文本后才执行。借剪贴板同步时原数据只在内存保存并恢复，不输出或保存用户剪贴板。
- SCP超时保留部分文件，先核原传输已终止、目标大小与剩余空间。原可信SFTP可用时续传同一文件，完成后校验完整大小/SHA再解包验签；不重复整包覆盖未知事务。
- Mac升级使用已验证独立launchd守护、AbandonProcessGroup和原安装路径。比较主程序及助手BID/Team/DR/权限后再替换，保留旧包。原ID重连、实际只读工具、安装版本/哈希、原安装身份和实时房间均通过后提交健康ACK；守护退出、卸载登记后再次确认App存活。首次初始化remote_disabled不当作正常通过，继续恢复并复验。
- 无相关源码或输入变化的已通过证明可以复用；必须先核实际源文件/输入哈希相同，并在新回执写清旧证明来源与复用范围。不要改旧报告日期、PID或版本，不把复用说成新版本重新跑过。签名与包字节变化后的检查及覆盖后授权实测仍不可省略。

实证索引：项目ROOM_UI_SIGNING_CONTINUATION_20261013.md；四台Mac664覆盖、Windows664完整Release475.684秒和独立恢复、244PE暂存及9项凭据源码一致性。只证明对应阶段，七台Windows覆盖、长期稳定和完整G01–G10按台账继续。

- Windows 存活判断先调用 GetExitCodeProcess 并要求 STILL_ACTIVE（259），再读取创建时间核身份。已退出但进程对象仍被持有时，GetProcessTimes 仍可成功；不能据创建时间误判活着、重复升级或触发错误回退。2026-10-15 Windows58的前两次正常退出被错误判超时，v4补真实退出码后正常关闭并覆盖664、原ID实调及健康ACK、守护terminal0后存活通过；不要把该控制端误判当成产品不能退出。
- 安装器健康ACK有既定期限。新主进程启动后优先完成原ID/FP、真实MCP、实际版本与签名、小文件传输和实时默认房间核验，再写同一attempt/PID/出生时间绑定的ACK；不要先整理报告而错过期限。619首次因迟到未ACK真实回退，第二次即时核验后terminal0；保留失败，不重写历史。

- 桌面反射画面不是离线证据：2026-10-15 Windows617先前显示控制Mac的递归画面，缓存窗口/CLI打开也未证明新握手。回到已授权办公主界面，核对完整目标ID后点击真实“连接”，取得Windows本机桌面与原办公ID，再启动原564桌面快捷方式。不要在反射画面按坐标操作；恢复后仍核原仿真ID/FP、原事务与实时房间。
