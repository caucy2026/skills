# 六机集群房与百设备管理台：现场验收和排障（2026-09-30）

集群管理 API 是权威数据；网页只是它的实时视图。默认六机通用验收房 `f450c684b868292f67c534b793e26314` 中的六个仿真 ID 为 `1321656264`、`1554650784`、`4240650696`、`4456560334`、`5298938227`、`6192992780`。六台电脑是**一个房间的六个成员**，与系统预置的多端测试、内容、Apple/Microsoft 商店、多机联合验收等其他项目房不同；不要按“六台机器”创建六个空房间。后台已有历史演示房间也要保留，不因默认展示需求删除。

`GET /api/v1/manage/rooms` 应在每个房间返回已批准成员 `memberCount` 与最近 12 秒心跳在线的 `onlineCount`，网页标题显示“在线 N / 总数 M”。申请中、已拒绝和已撤销不计入人数。SSE 通知后重取快照，4 秒校准，刷新失败标明状态未知。网页设备一行展示名称、仿真 ID、办公 ID、最后在线和状态；在线绿灯，离线黑灯且有文字。详情展开后才加载能力描述、技能、模型/Key、任务/竞标、评分、连续在线和最近离线信息。服务端必须**在线优先**稳定排序，不能只在浏览器当页排序，否则第 2 页可能仍有在线设备。游标绑定筛选、排序组与本次心跳阈值，界面每页最多取 100 台；120 台（60 在线、60 离线）验收前 60 在线、首页 100、次页 20、无重复/遗漏。

本次开发发现原列表 SQL 只按设备 ID 排序，即使六台都在线时截图正常，也无法满足混合在线/离线和百设备要求。修正为服务端状态组排序和游标；回归 `test_acceptance.DesignAcceptance.test_UI_01_120_members_pagination_search_and_counts` PASS，完整六个房间/事件测试 6/6 PASS。58 升级时真实暂时离线，Chrome 页面显示“在线 5 / 总数 6”，五台在线排前，58 在末尾黑灯；恢复后管理 API 与页面变回 6/6 绿灯。房间卡片在标题显示人数，选中卡片的创建任务、改名、复制房间名均可操作；不把复制时附带人数。之前服务端 `SIMULATION_REQUIRED` 直接显示英文错误码，网页已映射成中文“请先在设备端开启远程仿真，并确认通道已就绪后再加入房间。”，其余已知错误码也做中文映射；接口仍保留稳定机器码供智能体调用。

验收时区分六个独立事实：成员获批、心跳在线、仿真 ID 真正可连、安装包当前运行版本、Harness 正常、任务实际完成。某一刻六个绿灯不能证明后五项。Mac 529 的本地网络权限弹窗、132 旧进程占端口、Windows 覆盖时仿真暂断都曾让页面短时变黑；先沿仿真技能的身份/进程/窗口/双通道排障，再用原 ID 与新鲜心跳恢复。当前 2026-09-30 两台 Windows 已签并运行 dev345，三台远程 Mac dev345，本机 Mac 尚为 dev344；全六机任务的执行/消息/验收还不能据 6/6 在线宣称 PASS。
