## 2. 执行规则与环境

### 2.1 结果和优先级

结果仅填 PASS / FAIL / NOT RUN / BLOCKED；不适用单独填 N/A 并说明原因。P0 为发布阻断；P1 为适用功能必测，未通过需修复或明确批准延期及风险；P2 为扩展兼容。本表新增次数是建议验收强度，不冒充已有产品性能承诺。

方式：自动＝可脚本/单测；真机＝必须实际会话验证，可部分自动化；人工＝真实手势、双屏观察或体验评估；后台＝需授权测试账号、策略或商城环境。

共同准备：最终签名 APK、上一正式包、候选 Git SHA 和完整差异；H730 双屏实机；授权 Windows 测试电脑；按发布支持范围准备 Mac/Linux；隔离的测试账号与目录；可控网络；正确商城基线/高版本包。设备地址以执行当天确认为准，不假定 172.21.16.24 永久在线。

测试文件：中文名/空格名、空文件、文本、图片、PDF、Office、小目录、10 MiB 随机文件；均放专用测试目录。鼠标测试使用可恢复的桌面测试图标、空白编辑器和长列表，不操作用户工作文档。

不自动支付、不改生产权益、不删除用户文件、不清应用数据、不覆盖系统属性、不重启业务服务器。权限撤销、网络中断、安装卸载、强制升级、系统显示模式切换先确认窗口和恢复方法。

### 2.2 通用选项验收模板

原表每一个选项、每一个枚举值都分别执行以下步骤，不能只点开页面：

1. 记录原值、实际可见/禁用条件和当前会话状态。
2. 改为目标值，观察 UI 回显，核对对应配置或协议行为。
3. 区分“立即生效”“下一会话生效”“仅当前会话”“全局默认”；用真实动作验证，不只看勾选。
4. 返回再进入、重启 APP、新建会话各核对一次；验证应持久的值保留、不应持久的状态复位。
5. 双屏另一个会话检查是否被错误影响；固定策略禁用项不能被高级入口绕过。
6. 恢复原值，验证行为恢复。删除、退出、锁屏等危险动作仅使用测试对象。

### 16.1 本次根因与实验留痕

- +316：加入有界硬解码失败回退，最终恢复 Mac 画面，但首次故障释放约 20 秒，不满足首帧要求。

#### 17.0.1 D2→D0 成功、D0→D2 失败的角色差异及候选改动原理

用户明确的两组操作是：（A）KEMI 主 Activity 在 PAD D2 启动，扩展画面在 D0，扩展屏应用列表中打开浏览器成功；（B）KEMI 主 Activity 在 D0 启动，扩展画面在 D2，同样操作出现投放失败。这里的 D0/D2 是 PAD 物理 Display ID，不是远端 Mac 的原屏/扩展源编号，也不是解码视频槽编号。`DualScreenController.externalDisplay()` 依据主 Activity 所在 Display 选对侧屏，`start()` 将原画面留在主 Activity 的 Flutter 画布，另在对侧启动 `ProjectionDisplayActivity` 承载扩展 Surface 和应用列表。因此 A/B 确实互换了 Android 显示窗口与 Surface 所在物理屏，不能仅因同为“扩展”就视作同一路径。

### 17.1 白盒取证与假期回归执行法

1. 每轮先固定 PAD/各远端的实际版本、进程路径、二进制 SHA-256、设备 ID、显示编号及时间基准；不要把旧安装服务或另一份便携候选的行为算进新版本。
2. 在切换前、切换时、首帧、打开键盘、英文/中文提交、扩展/收回、HOME/返回、断开时给每条操作记时间戳。同步截取 PAD `logcat` 中应用 PID 的 Flutter、键盘代理、Activity/Surface/MediaCodec 事件，远端对应会话/连接管理器/视频服务日志和 OS 崩溃事件；按同一时间窗关联 peer ID、session ID、request ID、显示 ID 与断开原因。若正式包日志保存在受保护私有目录，使用应用自身导出机制；不能因 `run-as` 不可用就虚称已读日志。
3. 用源码核对实际状态机：设备切换是否先预留目标再关闭旧会话、异步请求是否持有旧 session/peer、键盘焦点是否绑定当前会话、首帧前是否设置真实远端分辨率、分辨率变化是否重建解码器、扩展状态是否只在驱动确实可用时公布。对每个疑似竞态先写可证伪假设，再用日志和最小复现区分，不能只看最终截图猜原因。
4. 视频必须同时有动态画面帧推进、时间戳截图/短录屏、远端发送/客户端解码日志与 FPS 指标。静态桌面的 0～1 FPS 不能单独判故障，连接动画或黑屏也不能算首帧。每台目标至少驻留 2 分钟，期间前台/后台、键盘、输入和扩展操作连续进行。
5. 每 5～10 秒采集 PAD/远端进程 CPU、内存/PSS、GPU/渲染计数器和设备总负载；标注桌面是否动态、是否编译任务并行。比较同一负载下基线、峰值、稳态与断开后回落；没有 GPU API 时记 `UNAVAILABLE` 与替代采样，不填假值。
6. 失败即保存该轮操作表、三端日志窗口和制品身份，定位到源码路径后作最小修复，重编同一路线，再执行失败用例、相邻功能和完整 M01～M07。交付报告逐轮给 PASS/FAIL/BLOCKED 与证据链接，不能把部分通过概括为全功能稳定。
7. 复合操作按用户实际顺序连续执行：切换目标→核实目标身份和首帧→点远端文档→弹出 PAD 输入法→英文及中文真正落到文档→隐藏/切换键盘→扩展/收回→切另一台→重复。操作脚本须明确 PAD 显示编号；每步后检查是否仍为预期目标，不能因会话自动跳回而在旧目标继续计数。Windows `--cm` IPC 首次启动成功、连接关闭后再次启动报 `query_cm` 拒绝访问时，必须对照同一连接 ID 与首次 CM 生命周期判断主因；不能仅凭最后一条错误认定首次连接失败。
