# 行为合同与自动覆盖

## 建立有界兼容面

清单来自锁定原EXE／资源／配置的分派表、Menu回调、输入事件、网络入站与出站、对象工厂、状态调度器及资源加载分支。分别记录已枚举、已解释、已实现、已验证、矛盾、未知；不能将“扫描过所有函数”写成“理解并实现所有行为”。

建议用稳定ID连接以下表，沿用仓库现有格式，不先开发庞大管理平台：

| 表 | 最低字段 |
|---|---|
| 原版版本 | EXE／资源哈希、ABI、工具与原字节位置 |
| 行为合同 | ID、入口、状态所有者、前提、事件、状态转换、请求与回包、可见结果、失败／取消、资源依赖 |
| 数据绑定 | 对象类型／标志／资源键、对应行为ID、未知组合 |
| 用例 | 行为ID、条件、正常UI或协议诊断、步骤、预期边界与不变量 |
| 运行证据 | runId、角色与会话代次、实际端点、构建身份、原始引用及哈希、结果和适用范围 |
| 兼容差异 | 原行为、用户授权来源、替代行为、验收边界 |

新增字段或行为时先追加未知项，找到解释后升级；不通过缩小兼容面制造完成率。行为族数由实际清单生成，不能把NPC数量当行为族数。

## 一个合同必须覆盖完整生命周期

以库存为例，合同不能只写“0304=移动物品”。需要包含：

- 精确位置与容量、Object身份、数量或版本的区分、容器子槽。
- 空手／持物、模态窗口、源修订和会话代次。
- 整叠／部分取出、合并／交换／满格、预测后的两个端点。
- 请求成功的实际通知方式，发送失败回滚、服务器拒绝与纠正。
- 确认、取消、拖出窗口、窗口互斥、关闭、断线和重登。

以尸体为例，区分状态9、观察者关系、剧情入口、距离、输入锁、手持与服务器所有权。死亡不只是HP归零；是否改变关系、是否发新的入口标志，均从原版消费者和生产者确认。怪物尸体成功不能自动代表自己的尸体、他人保护期尸体、复活或召尸。

## 原算法移植记录

对每个状态转移记录：

```text
原版版本与函数／调用点
字段宽度、符号、单位、实例所有者
前态 + 输入事件
判断顺序及短路路径
每次状态写入／预测／撤销
发包、回包和广播的先后与接收者
资源创建、替换、复用、释放
候选对应模块与证据等级
未知项及下一次最小判别实验
```

原版观察者本地handle不能跨客户端复用；RoleID、ObjectID、资源ID和角色持久ID不是同一身份。先建立角色／会话／对象代次映射，再比较两端结果。

## 自动验证组合

1. **全量静态绑定扫描**：所有实际数据条目映射到合同、资源可解析且依赖闭包完整。检查动作表嵌套控件，不只扫显式visualStates。
2. **纯状态机与属性测试**：在有效前态上生成事件序列，核数量守恒、唯一手持所有者、非法输入无资产变化、取消无副作用、拒绝可恢复、旧代次不能改新对象。只对适用规则使用不变量，不强加原版没有的幂等性或ACK。
3. **原始证据回放**：固定原数据、输入与事件顺序，对比状态和协议；夹具必须追溯原运行或明确标为构造。预期结果不能由同一候选算法现算。
4. **正常UI端到端**：用真实命中与pointer/touch事件完成操作，跟踪进入共用状态机和发包路径。MCP的业务捷径是诊断工具，另标结果，不能升级为此层。
5. **双端同条件实机**：独立账号、可比角色、同图同落点、同视角、同状态；比较事件阶段和连续画面。截图、协议、持久状态各证明自己的层次。

分支覆盖率不是兼容证明；低频但高风险序列不得被pairwise覆盖或统计高分取代。改变共用模块时，通过反向依赖选择回归用例；发现新连带影响则扩大本轮范围。用例选择器漏依赖本身是缺陷。

## 渲染与时间

固定字体与UI在原逻辑画布上绘制；不在控件层偷偷缩放字体以凑截图。原资源更换背景不改变内部几何。

运动比较同时保留服务器坐标、客户端预测、远端插值、朝向、相机与ACT时钟；仅最终坐标相同不能算过程同步。法术按起手、结算、持续、覆盖、取消、到期和转场恢复分别比较。

确定性粒子可在锁定种子、步长和相位后逐步比较；随机输入未锁定时声明统计与时序等价范围，不承诺每颗粒子同像素。现场时钟、虚拟机tick和协议逻辑时钟分别保存；不能用校时、改超时或伪造心跳让故障消失后宣称原算法已还原。

## 覆盖完成的证据

一个行为族只有在其已枚举必要分支、资源、准入、失败与恢复和所要求的实机链均有对应证据时才关闭。纯客户端目标以原版客户端→原服基准和候选客户端→原服差分为核心；自服隔离夹具用于定位，不自动代替原服。原版客户端→自服等服务端终验只在本任务包含该范围时要求，不能扩大普通客户端修改范围。
