# SWDOL服务端兼容研发与收敛

## 目标与前置

先读用户最新需求、AGENTS、项目第一原则、现行技术主本、DEVELOPMENT_GOALS/STATUS、相关历史纠错和证据。项目路径现场发现。完整长期目标是原版行为的权威服务端，原版及我方客户端均能直接连接并完成全部游戏行为；14模块112门是拆分框架，不是范围上限。中期批次为Map00/01/04完整剧情及适用异常、重复与持久恢复；短期按执行账选择一个可关闭的完整行为门，不能擅自缩小用户目标。

本线程若是审查角色，只审文档/代码/证据和归并，不因此转成现场执行或修改共享源码。当前工作归属与环境以用户最新安排为准。本技能是方法，不声明全月已审完或产品通过。

## 修改已有算法：静态与动态双重兼容硬门

修改前锁原版、已验基线、候选源码/资源/配置身份，读完整相关依据及历史纠错。静态恢复调用者、直接/间接依赖、正常/拒绝/取消/到期/断线/恢复/保存分支；同时复用授权原版前后台动态注入，正常前台操作并观察后台裁决、协议、广播、状态及必要数据库。按同初态同事件定位首个分叉，不能凭截图、当前实现或组件绿色改旧算法。

已有原始动态证据仅在版本、前态和行为范围匹配且可复核时复用；不足或矛盾先做最小有界判别实验，不翻转常数。改前列本次缺陷、此前已验案例及依赖边界回归清单。改后同一候选制品重跑本项及受影响已验功能，失败/未验证/不可比较均不得关闭或发布。修A坏B保留失败与版本链，按既有回滚规则处置，不能靠重复重启或另补特例隐藏。

原版取证用[静态动态分析](../swdol-static-dynamic-analysis/SKILL.md)，执行用[XP控制](../swdol-xp-control/SKILL.md)及[动态跟踪](../client-server-dynamic-trace/SKILL.md)。180秒失败结束错误尝试、读成功记录和故障文档、纠正后续做；不把止损当整个目标停工。长周期业务观察保留实际合同范围，不为三分钟伪造到期/重生。技能不新增重启共享服务或改原服资产许可。

## 完成一个纵向行为，而非铺开功能

复用成熟路线：锁初态和合同 → 原版前台动作/后台观察 → 静态互证 → 类型化通用合同 → 我方实现 → 隔离差分/故障反例 → 同制品真实链路 → 重复/保存/恢复及受影响回归 → 证据关门。

A原客户端→原服；B最新我方客户端→原服；C与B同APP/资源→独立我方服，A/B定位客户端，B/C定位服务端；D原客户端→我方服是长期兼容终验。按每门适用链及用户要求执行；不同初态、相位或制品不得拼成通过。截图与后台、协议、即时DB、重登/冷重启分别证实，不能相互代替。详见[验收交接](../swdol-acceptance-handoff/SKILL.md)。

## 新账号、GM与三链现场闭环（2026-10-06用户要求）

本流程服务于与原版一致的完整权威服务端。优先关闭三地图的完整行为门；不能持续停在旧账号诊断、静态目录、组件或截图准备。

1. **新身份验证账号服务。** 为当前场景建立三个独立测试账号，原服A/B与我方C分别走已授权注册入口；生成新凭据只经私有内存/stdin。先核当前schema和账号服务实际结果，再用相同种族、职业、性别、属性、生日及外观参数自然创角、首次进图。记录账号→角色→会话/代次，覆盖重复、失败、正常退出和冷重登。账号不能创建、角色不能创建或不能首入，就记功能未完成；管理员双库登记、假SMS proof或直接0200诊断各自标范围，不冒充产品注册/自然创角通过。
2. **GM作为正式调试依赖。** 复用原服已授权GM身份，并验证我方有可用GM身份和权限。先通过正常命令入口对新测试角色进行同等级/装备等配置对齐，记录命令语法、操作者权限、目标、前后值、提交/审计、协议结果及冷读回。普通角色拒绝、失败和同一明确请求的重放不得额外发放；两次主动输入相同命令属于两个意图，按原版各自裁决，不能按文本去重。原版目标未命中或权限不足可能回退自身，发送前核目标活动身份与权限，防止误改旧GM资产。目录、解析器或组件不等于命令已接通；不直接写DB资产冒充GM。GM预置是明确夹具，不能替代注册、自然建角或升级/获取物品本身的验收。
3. **原版前台操作必须关联后台。** 按成熟技能在线核当前原服身份及既有观察器/采集器，正常前台触发，同时观察原版裁决、输入/输出、协议、权威状态和即时DB。先找最早分叉并静态互证，再实现我方共用算法。没有后台因果证据不关闭服务器行为门；未知不按角色名、地图或剧情补数值。
4. **同条件三链同组验收。** A原版客户端→原服、B当轮完整最新我方APP→原服、C与B同程序及资源SHA的APP→独立我方服。独立可比角色可同时登录，在有界同窗执行同动作；同账号不得争登。每个剧情阶段在既有网页同一组固定A/B/C三槽，三张未修改整帧可点击放大，标时间、初态、阶段、制品SHA和后台/协议/DB引用。缺一链、条件未对齐或B/C身份不同保持未通过；不能用两张图、旧图、三张我方图或复制图补位。截图齐全是必要门，不替代后台、失败/取消/重复、保存和恢复证据。最终D原版客户端→我方服仍须单独完成。
5. **先一条完整链再扩覆盖。** 先完成一个代表角色/场景的上述全链，按首差异修通用状态机和数据来源，再覆盖八职业、三地图及剩余门。物理10击和全部已学技能等用户指定分母保留；单次魔法不估计样本方差，非伤害/非法目标另有判据。每次交接列实际新增闭合门、失败及唯一下一动作，不以文档/构建数量代替成果。

在线注入与具体账号注册、XP/MCP输入、GM权限、三分钟回查和清理分别复用现有动态、数据库及验收技能。不停启用户负责的地图，不抢同事XP或端点，不加载重叠探针/第二采集器；既有载荷不能扩点时先核成熟无重叠在线方案并隔离验证，不能把某一载荷限制说成一般在线注入不可行。

## 通用实现与可追查核心要求

- 玩家、NPC、怪物、Boss共享类型化身份/代次及生命周期合同；RoleID、ObjectID、连接局部句柄分开。数据定义、裁决状态、协议投影、持久化和客户端显示分层，一份事实一个所有者，不按名字/地图/单个Boss补丁。
- 实现须可扩展、可读、低耦合、故障可追查。复杂规则落已有共用核心，不另建竞争状态机；接口明确前置、结果及错误类别。源码实际锁与事务顺序必须审查，不仅提出架构图。
- 用明确状态所有者和串行裁决边界控制并发；核跨线程消息、对象代次、队列、锁获取顺序、超时与回调。避免持锁网络/跨服务等待；只有实际锁图与异常/并发证据支持时才称无已知死锁，不能承诺零bug。
- 交易、奖励、扣点、充值和市场等按实际持久合同审查提交点、原子性、版本冲突、防重与恢复；资产变更不能仅靠下线保存。记录关联ID、身份/代次、资产版本、来源去向、前后值、提交结果和失败类别，脱敏且有界。不得将我方事务设计说成原版已证算法。
- 区分缺档、坏档、存储失败；不能以同一空返回静默覆盖坏档。计费未知频率、连接阶段和充值并发先查原版，不发明常数。数据库接入复用[数据库技能](../swdol-database-operations/SKILL.md)。

## 防止越做越散：在途限制与关门

用户明确给出多条链路时，必须在同一工作周期同步推进，按[多链路执行规则](../swdol-acceptance-handoff/references/outcome-self-review.md)拆依赖、复用共同工作、逐线验收；不得只做一条而长期搁置其余。用户未要求多线时集中完成当前主要验收门；多线任务每线仍保持唯一当前门，避免不断铺开而不收尾，不能为收敛删需求。

新发现统一进入现有技术主本/执行账：区分本门必需依赖、回归、独立缺陷和未来扩展，先去重。同技术链只维护一个规范主本；正确后续结论基于证据覆盖旧判断，失败与原始记录保留。无需当前门的扩展排队，不顺手实现。

每门固定范围、可比前态、预期、覆盖、证据、负责人、失败/阻塞、唯一下一动作和关闭条件。当前门必要依赖解决并整门验证后再开下一门；若真阻塞，记录具体缺失与恢复条件，推进已排队独立工作，不宣称该门完成。方法失败转成最短复现和修正路线，禁止同一无新证据循环。

收敛以业务门和高优先级问题的实际关闭为准：报告新增/关闭/重开/净未完成门、最老未关闭项、在途数量、回归和缺证据。不要把文档数量、代码量、构建、15/15施法事务或框架完成当作原版视觉、持久化、重登或全部技能通过。发现新分支保留分母，解释新增范围；不能为提高百分比移出失败项。

每两小时按用户频率交付：当前门结果、可确认新增、差异/纠正、剩余与下一动作、同制品证据、选择性备份状态；实际回读远端SHA才称上云。报告后续做，不删除/缩小/虚假完成目标。完整验收前不随意推广候选，保留回滚。全局技能完成不等于研发目标完成。

## 客户时间效率优先

按用户要求，客户时间和目标完成效率是第一优先级。先复用成熟技能、现行合同、成功记录与已准备工具，选择能定位首次分叉并关闭当前完整行为门的最短路线。一次真实动作尽量同时取得前台、后台、协议与数据库证据，各层仍分别判断。

不要做过重或重复的内部测试：先完成最小判别实验及与改动直接/间接相关的必要回归；只有新增失败、变化或未解决风险才扩大检查。无相关变化不反复全仓构建/重跑；不以大型框架、无关重构、无限组合穷举或自实现round-trip代替客户可验收结果。独立准备可并行，现场输入和共享写入按资源归属顺序执行。

效率不能靠删需求、改验收标准、漏保存/重复/恢复边界或省略已明确要求的静态与原版动态双重核查取得。正式交付仍满足现行必要硬门，同制品受影响回归不能省。三分钟失败回查文档纠正后续做，不反复盲试；报告实际耗时、当前门是否关闭与唯一下一动作，而不是代码量或测试数量。

## 停工前报告与继续推进义务

按用户要求，没有明确且有证据的完整停工理由，不得主动停止研发。单次失败、三分钟超时、报告已发、临时聊天、构建等待或阶段结束都不构成整个目标停止的理由；先纠正失败路线，并继续不依赖阻断的分析、实现、验证或整理。

确实无法继续时，在停止前必须向用户报告：当前完整目标和可确认进度；本轮实际完成及未完成；阻断的具体动作、阶段、错误与证据；已尝试的方法及结果；为何没有可推进的独立事项；需要的外部变化或授权、恢复条件和恢复后的首个动作。不能用笼统“环境有问题”或“暂时无法完成”代替。

报告阻断不等于获得暂停许可，不得擅自删除、缩小或标完成目标；目标状态按实际工具规则处理。用户明确要求暂停则立即遵从，不为补齐报告继续业务操作。报告不能承诺工具未支持的后台持续执行。
