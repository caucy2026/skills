# 权威算法一致性、稳定性与多角色验收

适用：SWDOL服务端行为重建、算法实现和交付验收。本文是执行方法，不是通过记录。遵守第一原则、当前聊天目标及授权；共享主源码，隔离构建/DB/端点/证据，不占同事VM或采集器。

## 证明范围与可比条件

A原版XP→原服；B当轮完整最新APP→原服；C与B同程序/资源哈希APP→独立我方服；D原版XP直接→我方服。A/B定位客户端，B/C定位服务端，D验证原版兼容。三链要求不得省略；顺序实验不能冒充同窗。有限样本只能证明声明的版本、条件和范围，不证明所有未知场景。

每个算法先写可证伪问题，例如“同初态取消Plot601是否终止等待且不改变资产/Mark”“两个角色同时拾取同一掉落是否只授予一次”。锁定源码HEAD及脏输入哈希、APP/服务端EXE/资源/配置SHA、地图实例、会话代次、运行对象和时间窗。初态包括角色职业/等级/技能、位置/朝向/HP/MP/状态、装备/包裹/手持/银行/钱/Mark、NPC实例、仇恨/计时器、队伍、资源和随机输入；按问题选择必要字段，未知关键字段记不可比较。使用独立可比角色，不争用账号，不用GM修改原服状态充当自然行为。

## 前端操作与后端注入如何验证算法

1. 先查原EXE同哈希的静态调用链与结构布局，确定输入解析、条件读取、裁决、状态写入、广播、保存的所有者。探针位置必须绑定二进制SHA/原字节；函数名或一条旧注释不能证明身份。
2. 复用唯一常驻观察器。热探针只复制必要寄存器/字段及有界原始字节后立即返回，不修改结果、不做网络/格式化。记录目标PID、payload代次、探针原字节/安装字节和心跳。INJECT_OK不算业务证据。
3. 用MCP公共UI入口点击/选择/施法/走路，先保存正常界面与前态。确认工具调用走正常界面/输入路径；直接发业务包只计协议诊断。连续批次预先准备，不在进图后构建或研究。
4. 开启有界窗口，关联“UI意图→出站完整帧→后端解析→读取条件→裁决/状态写入前后→广播→客户端应用→画面→即时DB”。关联键是runId、session/generation、Section、actor/handle、opcode、序列和时间，不能只看名字。没有事务ID时说明时间关联强度与竞争风险。
5. 后端同一点的before/after证明该字段变化；独立协议、客户端与DB证明变化是否被发布/保存。不能拿同源两个探针当两个独立证明。截图只证明显示，不证明持久化。
6. 将观察变成通用状态机/字段/边界合同，再实现和建立原始帧重放测试；不得按账号、地图、NPC/BossID补结果常量。用C同初态实际重跑，对比规范化语义与原始差异，最后D复核。
7. 失败取消重复、断线/超时、正常退出、进程冷重启与重登均检查即时及恢复后状态。结束stop→sealed→本地归档SHA/readback→远端精确清理→archived确认，所有权或代次变化就停止写共享窗口。180秒恢复止损与三次同路线熔断沿用XP技能。

确定性输出应逐字段/逐字节相等。会话ID、时钟等易变字段只在有依据时映射，保留原始值及规则；不能“归一化”掉业务差异。随机伤害/掉落要锁随机输入或做预先定义样本规模/置信区间的分布比较，不能要求某一次随机值相等或仅凭均值宣称一致。时序阈值来自原版实测及任务合同，不能事后放宽。

## MCP多角色：仿真与真实验收的边界

先确认工具能否指定每个会话。单一全局socket的MCP不能用连续launch切账号冒充并发；close_client也不能误关其他角色。若工具不支持会话选择，应先实现/验证隔离会话路由，保留现有单会话接口兼容，再运行多角色。每个实例有唯一账号/角色、PID、socket、代理端口、manifest、日志及DB身份，并核实际运行程序/资源哈希相同。客户端连接我方权威服，不用客户端自算替代服务端裁决。

编排器维护角色→PID/socket/session/handle映射，在所有角色worldReady且原服/我方前态可比后设置共同屏障t0；用单调时钟排定动作，记录实际提交及到达偏差。并行输入仅用于互不争用的客户端；同一宿主焦点或共享输入锁必须串行，注明偏差。没有真实并发能力则只记顺序测试。

角色分工：攻击者提交技能/普攻，目标执行移动/防御/取消，旁观者检查AOI与广播；组队者验证组队规则及奖励。用双方和旁观者的权威状态/画面/协议核同一事件，检查重复、漏播、幽灵实体和最终一致。场景按合同包括：互相移动/追击、同时攻击/死亡、Boss仇恨切换/阶段/召唤/双人奖励、同物拾取/交易竞争、队伍进出、跨图AOI、离线重连/冷重启、多角色持续运行。不要把两个自己的APP连接我方服替代A/B或D。

算法回放/模拟器可批量生成边界、乱序、重复和并发序列，适合发现问题及回归；记录输入种子和失败最短序列。它们只算组件/协议层，不证明原版UI、真实多人、网络时序或产品使用性。

## 稳定性、可靠性与使用性验收

- 稳定性：按预先声明的角色数、动作率、地图、时长跑持续场景；记录RSS/CPU、队列、帧率、请求延迟分位数、DB延迟、错误/断线/重连、实体/会话泄漏，热身与测量区间分开。结束正常退出及冷重启后验证恢复。不能由短跑外推百人/长稳。
- 可靠性：正常成功、边界值、拒绝/资源不足、取消、重复请求、网络延迟/断线、保存失败及进程重启；验证不会重复扣款/奖励、资产守恒、单一所有者、状态转移合法、保存原子性及重连不复活已取消动作。故障注入仅在隔离我方服和测试DB，不破坏原服服务。
- 使用性：真实注册→登录→原生创角→首图、任务触发/选项/反馈/返回、技能/物品/组队/Boss、失败提示与恢复、正常退出/重登。保留前中后截图与实际操作记录，检查玩家能看到并完成动作；工具返回成功、非黑屏或actorSubmitted不替代玩家可见结果。

## 逐门记录与最高效次序

先选一个最小完整业务闭环，资料/制品/采集/DB读取器在操作前准备，暖会话连续取前态→动作→后态；复用成熟只读DB适配器，不每次重新编译部署查询工具。用同一动作覆盖协议/权威/持久化多层，但每层独立判定。真实失败先定位最早分歧，修通用算法后只重跑相关依赖及必要回归；不要靠重复重启获得偶然成功。

每门保存：gateId、问题、链、初态、动作/实际时序、期望与观察、原始证据路径/SHA、差异、制品身份、状态、阻塞、下一动作。状态为PASS/FAIL/INCOMPARABLE/UNVERIFIED；组件/离线/模拟通过另有分母。缺任一合同必需证据不计业务门。两小时报告实际北京时间窗口、完整门新增数、失败/不可比较/组件分母、身份与证据、资源健康、下一动作、选择性审查备份分支及远端回读SHA；不上传凭据、原始DB或私人迹线。

当前示例（2026-10-03，非完整门）：最新APP在原服Plot601正常取消，角色body及装备/手持/Mark双读取前后hash一致，窗口10有界归档5760字节并确认archived。仍需解码目标业务事件、完整影响字段及A/B/C同初态同窗和D；不能据此声称Plot601、三地图或112门通过。

## 操作前固定合同，交付可复查证明

每项执行前先保存带SHA的验收合同：算法范围、状态机/输入类别、各前置条件、输入动作、可观测输出、保存不变量、允许差异、时序阈值、重复次数/随机样本计划、负例、需要的A/B/C/D链和通过条件。执行后修改标准意味着新合同、新一轮验收；原结果仍按旧合同保留，禁止事后放宽。

标准的来源必须可追溯：用户产品要求＋同哈希原EXE/资源的静态调用链＋原服真实正常操作。静态推导与动态观察分别标记，存在冲突先实验判别。没有原版证据的部分只能是待证假设。期望值不得由我方实现自己生成再让同一实现判断PASS；原版独立观测是行为基准，审查者能从原始帧/DB/截图重算结论。

覆盖表在执行前列明：状态×输入类别×边界×角色/地图×失败/重复/恢复。按可达到的业务等价类选代表，再补边界和跨状态组合；说明未覆盖部分，不用几个成功样本证明全算法。并发需明确可接受串行结果集合、唯一授予/资产守恒/广播一致等不变量；乱序和时序敏感行为另测。回放用于证明实现遵守已核合同，真实三链及D用于证明外部行为兼容，两类证据不能互相替代。

交给用户的每门验收包包含：
1. 已固定合同及SHA、覆盖表与未覆盖项。
2. 原版与候选源码/程序/资源/配置身份及可比初态；差异或未知项明确列出。
3. 可复跑步骤/公共UI动作或MCP编排、角色与端点所有权、实际时间窗和退出/恢复步骤。
4. 前中后画面、完整协议、探针事件、即时和重启后DB差分的证据索引及SHA；私人原始证据只存受控本地，分享脱敏派生结论。
5. 自动比较输出及逐字段差异、归一化规则、独立不变量检查；保留失败样本和最短重现序列。
6. 每个判据PASS/FAIL/INCOMPARABLE/UNVERIFIED及理由；全部必需判据通过才请求用户确认该门，缺证不以文字总结覆盖。

用户验收按合同逐项回读：确认版本→核初态→执行正常动作→核原版/候选差分→检查保存/重复/恢复→核覆盖与限制→确认这一门。给出明确门ID、复查命令/入口、预期可见结果和证据位置，不要求用户接受笼统“功能完成”。没有用户确认也不能伪造“用户已验收”；技术通过与用户确认分别记录。

这里提供的是可重复、可反驳的工程证明，不是对无限输入的数学全称证明。只有存在形式化模型及机器检查证明时才声明形式证明；它仍需要验证模型与真实原版的对应。当前未验业务保持OPEN，不将方法文档本身算作通过。

## 危险地图复活与取回装备：门口安全召尸（用户明确要求）

用户确认危险地图都有召尸NPC。先查本图门口当前服务NPC（主池、附加池及实际剧情槽），按正常服务把自己的尸体召到门口安全区，再让尸主返村、药师门口复活、尸主跨图回门口拾装。禁止按尸体数据库坐标直接走进危险区；未找到NPC不能以危险寻路替代。核附近敌对实体及攻击事件，安全站位、尸体owner/代次、正常NPC响应及前后位置截图齐备后才继续。

2026-10-03反例：直接向Section5旧尸体寻路，初态有66级敌对Object21517/handle34，随后施法目标为受控handle35；新尸体43出现在最后位置，经验减少219143且迁至Section10。旧尸体本身不是已证死亡原因，完整击杀链尚缺。原服失败不可用隔离测试补成成功。


## 跨服复活闭环：执行与用户复查共用清单

先固定角色、尸体owner/实例/代次、药师、技能定义、原版程序与数据身份。地图编号变化不自动证明跨服：分别记录来源和目的地图进程/端点、会话及权威所有者交接；同进程切图与跨进程迁移分别判定。每阶段保留前后权威字段、完整协议、客户端显示与即时DB；没有捕获的时点写未知，不从最终差值推断执行时点。
