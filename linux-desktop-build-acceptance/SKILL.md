# Linux 桌面编译与真实验收

适用于跨项目复用。先遵循项目AGENTS、本机LOCAL规则及原成功构建；若项目有执行资格台账，使用实际会话身份运行其最新main检查器。本技能不创建额外审批，也不把某台机器、Ubuntu版本或某次失败写成全局限制。

## 最短实施路线

1. 冻结本次实际main、Linux增量、CPU架构、SDK/锁/原生生成器、运行账户与旧安装身份。用隔离输出保留主线新功能和旧版有效Linux适配，不整体提交共享脏树。版本核pubspec/AppVersion、生成资源、完整包和实际运行进程；只改CLI build-number不充分。
2. 原成功环境逐项传给**同一阶段**：绝对cwd、PATH、CARGO_HOME/RUSTUP_HOME、PUB_CACHE物理路径、PKG_CONFIG_PATH、编译器/链接器及原生target。先用相同环境验证依赖、协议/桥接及可用字节，再开始大量写盘。缺依赖先定位，不先全局升级SDK或清空工具链。
3. 使用已验证的本机架构构建入口，生成一致的GUI、AOT、插件、helper和SDK；复用原生组件时核生成前的实际输入与最终字节，不能复制旧stamp或只替换AOT冒充整包。用户指定并发则真实设置和观察；失败不能悄悄降并发后仍称原并发成功。
4. 真机验证必须绑定最终候选/进程/出生时间：中文、鼠标键盘/文件、启动更新与身份、所请求功能、资源与日志。修复前负控→源码/组件→实际界面→最终包装/覆盖是不同证据；不要相互替代。按任务范围补缺，不机械恢复已取消的大规模验收。
5. 新阶段前后测实际空间，按`kemi-storage-cleanup`核归属与引用后清理已结束生成物；云构建另按`cloud-build-cleanup`收尾。保源/Git、原SDK/依赖、身份、用户数据、最新正式包与必要证据。提交写实际Session-Name/ID及影响/验证/缺项。

## 按症状读取

- 中文方框、旧版正常新版乱码、字体虽在却不显示、黑色圆角：读[字体与透明窗口](references/fonts-and-windows.md)。不要一律安装系统字体或改locale。
- 环境、并发、协议、SDK、权限、测试与打包反复出错：读[常见错误和纠正路线](references/common-failures.md)。只读对应行与相关项目记录。
- GLIBC/CPU不匹配：可用只读探针`python3 scripts/probe_elf.py --elf FILE --target-arch arm64 --max-glibc 2.31`。最后参数仅示例，按本次真实目标设置；它不加载/执行候选，也不证明完整依赖、硬编、界面或发布通过。`--self-test`验证探针。

## 兼容与性能的判断边界

- 区分构建机、目标系统和每个进程的运行时。GLIBC目标由用户与项目决定，不能永远硬编码Ubuntu20/2.31。用户允许新版本时，可验证既有新运行时/隔离codec进程等最小方案；记录实际支持范围，不把“旧基线不满足”当永远无解，也不未经评估替换共享系统libc。
- H.264/H.265名称可能是软件编码；只在媒体任务中核实际硬件后端、库可加载、真实关键帧和端到端解码。开关为开、驱动节点存在或FFmpeg注册名称都不是硬编成功。
- CPU按实际进程族、单核等效口径及项目门槛；不能除以核心数制造通过。UI跟随vsync、局部更新、离屏停止绘制，真实计时继续；计算重活才进入有界worker。并发数由请求、资源和原门禁共同决定，不给所有机器固定j8/j16。
- 性能报告给同机同场景的样本数、p50/p95/max/失败率、CPU/RAM/swap和候选SHA；没有实测不报提速百分比。项目G6或指定轮数继续遵守，不凭本技能为无关应用新增统一门槛。

## 接回专项流程

VibeKits用`vibekits-linux-release`；远程办公用`kemi-remote-office-release`；纯Rust服务用`rust-linux-cross-build`。仿真用`vibekits-remote-simulator`，断联先对账原事务再用已登记备用恢复，回到原通道验证。内部商场/Common分别沿原发布技能，不改App身份、不用ARM包覆盖x64同一下载地址。

仅创建或更新本技能不等于编译、系统升级、设备操作、同事通知或商城发布；对应动作仍以当前用户任务与实际工具权限为准。
